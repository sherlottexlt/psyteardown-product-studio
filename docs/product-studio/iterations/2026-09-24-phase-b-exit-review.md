## 目标

Phase B 的退出门槛是：**从模糊意图到可运行 Web 产品、自动测试/修复、反馈和导出全链路可演示且可恢复**。

本次复核需要：

1. 验证 B1–B9 是否已满足 Phase B 退出门槛；
2. 识别当前实现与退出门槛之间的差距；
3. 决定这些差距是否必须在 Phase B 内关闭，还是可以推迟到 Phase C 或后续；
4. 记录 Phase B 已验证的能力边界与未验证的约束；
5. 明确 Phase C 的前置条件与首个工作包。

## 非目标

- 不实现新功能；
- 不修复已知但不影响退出门槛的缺陷；
- 不为 Phase C 预先设计架构；
- 不把"本地切片已验证"升级为"生产就绪"或"真实结果已证明"。

## 差距汇总

### 必须在 Phase B 关闭的差距

**无**。Phase B 退出门槛是"可演示且可恢复"，不要求"生产就绪"或"真实模型稳定"。

### 可以推迟的差距

以下差距已明确记录，但不阻塞 Phase B 关闭：

1. **真实 provider 接入**（Product Contract 与 Thesis）
   - 当前：fake provider 转述已确认输入
   - 影响：无真实研究、推理与外部事实发现
   - 推迟原因：需先决定输入保留、费用与失败重试边界
   - 推荐处理：Phase C 或独立工作包

2. **部署级 OS/container 隔离**（B4 执行）
   - 当前：本地 allowlisted subprocess
   - 影响：无多租户隔离、无资源限制、无恶意代码防护
   - 推迟原因：本地验证足以证明执行框架正确性
   - 推荐处理：Phase D 或真实多用户部署前

3. **视觉回归与跨浏览器 Gate**（B4 验证）
   - 当前：Chromium 截图存在但无基线比较；无 Safari/Firefox/移动
   - 影响：无视觉一致性保证、无跨浏览器兼容性保证
   - 推迟原因：基础 Playwright/axe 已足以证明验证框架
   - 推荐处理：Phase C 或真实用户试用前

4. **真实模型修复**（B5）
   - 当前：deterministic planner
   - 影响：只能修复模板已知的固定失败模式
   - 推迟原因：受限修复框架与安全边界已验证
   - 推荐处理：Phase C 或真实 provider 接入后

5. **交付包签名与部署**（B6）
   - 当前：未签名、未部署
   - 影响：无发布渠道、无部署自动化
   - 推迟原因：本地导出已足以证明交付框架
   - 推荐处理：Phase D 或真实交付需求出现后

## Phase B 已验证的能力边界

### 可以声称的能力

1. **Product Contract 工作流**：从模糊意图到四个上位对象的完整 proposal/correction/confirmation 工作流，包含 revision、stale、冲突与恢复语义。
2. **Thesis 比较与选择**：可以生成并比较多个机制/实现不同的 Product Thesis。
3. **Web 产品生成**：可以在受限 workspace 中生成 React/TypeScript/Vite SPA 源码。
4. **本地执行与验证**：可以在本地 subprocess 中安装依赖、构建、运行并用 Playwright/axe 验证。
5. **受限失败修复**：可以对已知失败模式执行白名单补丁修复，并在新的 generation lineage 中重新验证。
6. **预览与显式反馈**：可以在沙箱 iframe 中预览产品，并记录需要显式同意、可撤回、锚定到 revision 的反馈。
7. **反馈驱动迭代**：可以让一条反馈驱动同一契约的下一 proposed revision，并生成版本差异。
8. **可追溯导出**：可以导出内容寻址、字节确定的交付包，包含源码、构建物、验证产物与交付说明。
9. **全链路可恢复**：所有 Job 可以在 SQLite 重启后恢复；revision 冲突可以保留草稿并恢复。

### 不能声称的能力

1. **真实研究与推理**：当前 provider 为确定性 fake，无网络、无真实模型推理。
2. **生产级隔离**：当前执行为本地 subprocess，无容器、无多租户、无资源限制。
3. **跨浏览器兼容性**：只验证了 Chromium，未验证 Safari/Firefox/移动浏览器。
4. **视觉一致性**：截图存在但无基线比较，无视觉回归检测。
5. **真实用户结果**：所有验证为软件测试与本地预览，无真实用户试用或任务完成观察。
6. **模型修复稳定性**：deterministic planner 只能处理已知模式，无真实模型修复。
7. **发布与部署**：交付包未签名、无部署渠道、无发布自动化。

## Phase B 退出决策

### 决策 1：Phase B 是否可以关闭？

**建议：是**。

**理由**：

1. Phase B 退出门槛为"从模糊意图到可运行 Web 产品、自动测试/修复、反馈和导出全链路可演示且可恢复"；
2. B1–B9 已实现并验证了完整链路；
3. 真实 provider、部署级隔离、视觉回归等差距已明确记录，且不影响"可演示且可恢复"这一核心退出条件；
4. 继续在 Phase B 内实现这些能力会延迟进入 Phase C（真实结果验证），而 Phase C 的现实任务观察才是评估产品价值的关键。

### 决策 2：哪些差距必须在 Phase C 开始前关闭？

**建议：真实 provider 接入（至少一个端到端真实链路）**。

**理由**：

1. Phase C 的目标是"真实结果验证"，需要真实生成的产品才能进行真实任务试用；
2. fake provider 只能转述已确认输入，无法发现新的外部事实或生成有意义的产品；
3. B7m 已证明真实模型源码生成可以在一次运行中成功，但需要更多运行来评估稳定性；
4. 部署级隔离、视觉回归等可以在 Phase C 中逐步增强，不阻塞首次真实任务试用。

### 决策 3：Phase C 的首个工作包是什么？

**建议：C0 — Phase C 前置：真实 provider 接入与端到端链路**。

**范围**：

1. 决定真实 provider 的输入保留策略（哪些字段保留？保留多久？）；
2. 决定真实 provider 的预算与费用计量（金额预算？token 预算？失败重试？）；
3. 实现至少一个真实 provider 适配（推荐：DeepSeek 或 Claude，已在 B7m 验证过）；
4. 从 ProductIntent 到 B6 交付包跑通至少一次端到端真实链路；
5. 记录真实链路的失败模式、成本与时间；
6. 不要求多次稳定运行，只要求证明真实链路可以完成。

**退出门槛**：至少一次从真实 provider 生成的 Product Contract 到真实模型生成的 Web 产品，并成功导出交付包。

## Phase B 遗留项

以下问题已在 Phase B 中发现，但不影响退出：

1. 预览端口固定为 4173，同一时刻只能运行一个执行（B4 约束）；
2. 没有常驻 worker，Job 需要客户端显式推进（A5/B3 约束）；
3. 没有项目列表/恢复界面（A5 约束）；
4. 全量测试仍有 Pydantic 字段遮蔽和 FastAPI TestClient/httpx2 迁移 warning（不影响通过）；
5. B5 修复只允许固定模板白名单路径（B5 明确边界）。

这些遗留项已记录在 `CURRENT_STATE.md`，可在后续工作包中按优先级处理。
